# 이미지 경로 및 리소스 설정 현황

메뉴 이미지가 `GET /images/파일명` 요청 시 404가 나는 원인과, 현재 코드에서 어떻게 작성되어 있는지 정리한 문서입니다.

---

## 1. 백엔드 (Spring)

### 1) WebConfig.java

**경로:** `backend/src/main/java/com/new_cafe/app/backend/config/WebConfig.java`

- `WebMvcConfigurer`를 구현하고 **`addCorsMappings`만** 오버라이드해 두었음.
- **`addResourceHandlers`는 없음.**  
  즉, `/images/**` → `file:./upload/` 같은 리소스 핸들러는 **현재 코드에 없음.**

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
```

### 2) application.properties (static 리소스)

**경로:** `backend/src/main/resources/application.properties`

- 정적 리소스는 **요청 경로 그대로** `file:./upload/` 아래에서 찾음.
- 따라서 `GET /images/파일명` 이 오면 `upload/images/파일명` 을 찾고, 실제 파일은 `upload/파일명` 에만 있어서 **404** 발생.

```properties
spring.mvc.static-path-pattern=/**
spring.web.resources.static-locations=file:./upload/,classpath:/static/
app.upload.dir=./upload
```

## 2. 프론트엔드 (Next.js)

### next.config.ts (rewrites)

**경로:** `frontend/next.config.ts`

- `/images/:path*` 요청을 백엔드로 보낼 때 **경로 앞의 `/images` 를 제거**해서 보냄.  
  → 백엔드는 `GET /:path*` (예: `GET /파일명`) 만 받음.
- **요청이 Next를 거치면** 백엔드는 `upload/파일명` 만 찾으면 되어 정상 동작.
- **요청이 백엔드로 직접 오면** `GET /images/파일명` 이 되어 `upload/images/파일명` 을 찾다 **404** 발생.

```ts
async rewrites() {
    const backendUrl = BACKEND_BASE.replace(/\/$/, '');
    return [
      {
        source: '/images/:path*',
        destination: `${backendUrl}/:path*`,
      },
      {
        source: '/upload/:path*',
        destination: `${backendUrl}/:path*`,
      },
      // ...
    ];
}
```

## 3. 배포 / 리버스 프록시

- 저장소 안에는 **nginx 설정 파일이나 리버스 프록시 설정 파일은 없음.**
- `docs/502-ERROR-TROUBLESHOOTING.md`, `docs/DeplyGuid.md` 등에서 `proxy_pass`, 리버스 프록시 얘기는 있지만, **실제 `/images` 를 어디로 보낼지에 대한 설정은 레포 코드에는 없고**, 서버(또는 호스팅) 쪽 nginx/프록시 설정에만 있을 가능성이 큼.

---

## 4. 요약

| 구분 | 현재 코드 상태 |
|------|----------------|
| 백엔드 `/images/**` 전용 핸들러 | **없음** (`WebConfig`에는 CORS만 있음) |
| 백엔드 static | `/**` → `file:./upload/` 로 요청 경로 그대로 매핑 (그래서 `/images/파일명` → 404) |
| Next.js | `/images/:path*` → 백엔드 `/:path*` 로 rewrite 되어 있음 |
| 리버스 프록시 | 레포 안에는 설정 없음 (서버 쪽에서만 존재) |

---

## 5. 수정 방향 (참고)

- **코드로 해결:** 백엔드 `WebConfig`에 `addResourceHandlers`로 `/images/**` → `file:./upload/` (또는 `app.upload.dir`) 리소스 핸들러 추가.
- **인프라로 해결:** 리버스 프록시에서 `/images/*` 를 **Next(프론트)** 로 보내도록 설정하여, Next의 rewrite를 타게 함.
