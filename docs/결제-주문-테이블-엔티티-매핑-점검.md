# 결제·주문 관련 테이블 ↔ 엔티티 매핑 점검

## 1. orders 테이블

### 스키마 (data.sql + 마이그레이션)
| 컬럼 | 출처 | NOT NULL | 엔티티 필드 | 저장 시 설정 |
|------|------|----------|-------------|--------------|
| id | data.sql | PK | id | IDENTITY |
| user_id | data.sql | | userId | O (주문자) |
| guest_email | data.sql | | guestEmail | O |
| guest_phone | data.sql | | guestPhone | O |
| status | data.sql | O, DEFAULT | status | O |
| total_amount | data.sql | O, DEFAULT | totalAmount | O |
| applied_user_coupon_id | V2 | | appliedUserCouponId | O (수정 시) |
| created_at | data.sql | | createdAt | O |
| updated_at | data.sql | | updatedAt | O |
| customer_id | V5 | nullable로 변경 | customerId | O (userId와 동일) |
| order_number | V6 또는 배포 DB | 배포 시 NOT NULL 가능 | orderNumber | O (ORD-yyyyMMddHHmmss-XXXX) |
| total_price | V7 또는 배포 DB | 배포 시 NOT NULL 가능 | totalPrice | O (totalAmount와 동일) |

**결론**: 모든 컬럼 매핑됨. `order_number`, `total_price`, `customer_id`는 배포 DB NOT NULL 대응으로 저장 시 값 설정함.

## 3. payments 테이블

### 스키마 (data.sql)
| 컬럼 | NOT NULL | 엔티티 필드 | 저장 시 설정 |
|------|----------|-------------|--------------|
| id | PK | id | IDENTITY |
| order_id | O, FK | orderId | O |
| method | O, DEFAULT | method | O (TOSS 기본) |
| status | O, DEFAULT | status | O (PENDING 기본) |
| pg_tid | | pgTid | O (완료 시) |
| amount | O, DEFAULT | amount | O (null 시 0) |
| paid_at | | paidAt | O (완료 시) |
| created_at | | createdAt | O |

**결론**: 모든 컬럼 매핑됨. `PaymentService.ready()`에서 amount null 방지, `PaymentPersistenceAdapter.toEntity()`에서 method/status/amount null 시 기본값 적용함.

---

## 4. 적용한 보완 사항

1. **PaymentService.ready()**  
   - `order.getTotalAmount()`가 null일 수 있어 `amount`를 `order.getTotalAmount() != null ? order.getTotalAmount() : 0`으로 설정하도록 수정.

2. **PaymentPersistenceAdapter.toEntity()**  
   - `method`, `status`, `amount`가 null이면 각각 `"TOSS"`, `"PENDING"`, `0`으로 설정해 DB NOT NULL/DEFAULT와 맞춤.

---

## 5. 요약

- **orders**: order_number, total_price, customer_id 포함해 모든 컬럼 엔티티 매핑·저장 로직 반영됨.
- **order_items**: 컬럼·매핑 일치, 누락 없음.
- **payments**: 컬럼·매핑 일치, amount 등 null 방지 처리 추가됨.

배포 DB에 위 테이블 외에 별도 컬럼이 있다면(예: Hibernate ddl-auto로 추가된 컬럼) 해당 컬럼을 엔티티에 추가하거나, 마이그레이션으로 스키마를 data.sql/엔티티와 맞추는 것이 좋습니다.
